# NixOS and Home Manager configuration

## Initial setup

Apply NixOS first, then the standalone Home Manager configuration.

```bash
sudo nixos-rebuild switch --flake path:.#lab
just home apply lab
```

Log in to GitHub and Tailscale.

```bash
# GitHub
gh auth login
```

```bash
# Tailscale
sudo tailscale login
sudo systemctl restart tailscaled-set.service
# Approve the advertised routes and exit node:
# https://console.tailscale.com/admin/machines
```

```bash
# Reload environment variables for Docker
source /etc/set-environment
```

## Update

```bash
just update
just apply lab
```

## Commands

NixOS and Home Manager are managed independently. NixOS controls system
services, drivers, and the login shell. Home Manager controls shell settings,
Git, and user packages.

```bash
just apply lab           # Apply NixOS, then Home Manager
just home apply lab      # Apply lab's user configuration
just home build lab      # Build without applying
just nixos apply lab     # Apply lab's system configuration
just nixos build lab     # Build without applying
just check               # Check the flake
just show                # Show configurations
```

`just home` and `just nixos` list their available commands.
Home Manager configurations are `lab`, `linux` (generic x86_64 Linux), and
`darwin` (Apple Silicon). Without a host argument, Home Manager selects
`linux` or `darwin` from the current OS; NixOS defaults to `lab`.

Host-specific user settings belong in `home/hosts/lab/default.nix`.
Shared user settings remain in `home/base/`.
macOS-specific settings and Ghostty integration are in `home/darwin/`.

## Shell configuration

Zsh plugins use Home Manager's standard options in
`home/base/shell/zsh/plugins.nix`: `zsh-abbr.abbreviations`, `autosuggestion`,
`syntaxHighlighting`, and `plugins`. Tool settings are in
`home/base/shell/tools/`, including `programs.eza` and `programs.starship`.

`zsh/deferred.nix` moves the initialization blocks generated by these standard
modules into deferred files. `zsh/default.nix` controls their execution order.
This adapter uses Home Manager's definition metadata; if an update changes the
expected blocks, evaluation fails with a message to review the adapter.
Completion, plugins, and tool hooks remain deferred; shared initialization
and aliases are loaded immediately.

Abbreviations are now managed by Nix in `zsh-abbr/user-abbreviations`.
For the first switch, an existing file can be preserved with Home Manager's
backup option:

```bash
just home apply lab backup
```

This renames conflicting files with the `.backup` suffix. If that backup
already exists, activation stops instead of overwriting it. Subsequent
switches can use `just home apply lab` or `just apply lab` as usual.

## CI and SSH public keys

GitHub Actions checks Nix formatting and flake evaluation on pushes to `main`,
pull requests, and manual runs. It discovers every Home Manager and NixOS
configuration and builds each on a matching Linux or macOS runner.
It does not activate configurations: existing-file conflicts, hardware behavior,
and SSH connectivity still need to be checked on the actual machine.

SSH login keys are fetched from the account in `settings.nix` (`githubName`).
`home/base/ssh-keys.json` pins their hash and records fingerprints for review.
Every day at 06:17 JST (best-effort schedule), or on a manual workflow run,
Actions checks the keys and creates or updates a PR when they change.
The PR lists added and removed fingerprints and runs the configuration checks.
Failed downloads, invalid keys, and empty key lists stop the update.

Enable **Settings → Actions → General → Workflow permissions → Allow GitHub
Actions to create and approve pull requests**. Automatic merging is not enabled.
The scheduled workflow starts after these files reach the default branch.
After reviewing and merging a key update, pull the changes on each machine and
run `just home apply <host>`; merging alone does not update installed login keys.
For emergency key revocation, update the actual machines immediately instead of
waiting for the daily workflow.

## Migration from integrated Home Manager

The NixOS configuration no longer includes the Home Manager module.
Build both configurations before switching, then apply NixOS followed by
Home Manager from the same terminal:

```bash
just home build lab
just nixos build lab
just nixos apply lab
just home apply lab
```

The NixOS switch removes the old `home-manager-kaito.service` and the
system-managed user packages. `just` remains installed by NixOS, and
`just home apply lab` uses the Home Manager version pinned in `flake.lock`,
so it works even before the `home-manager` command is installed.
The standalone activation installs the user packages in the user's Nix
profile. Log in again after completing both steps.

The old `just switch`, `just build`, and `just home lab` commands are replaced
by `just nixos apply`, `just nixos build`, and `just home apply lab`.
